# Démarrage local

Logopolis requiert Node.js 26 et npm 11. Vérifier d'abord le binaire effectivement employé avec `command -v node`, `node --version` et `npm --version` : le premier doit afficher une version 26 et le second une version 11. Docker Compose expose PostgreSQL 16 sur le port local 5433 afin d’éviter les conflits avec une instance PostgreSQL déjà présente. Il expose aussi Mailpit uniquement sur la boucle locale : interface sur `http://127.0.0.1:8025` et SMTP sur `127.0.0.1:1025`. Les variables shell `MAILPIT_UI_PORT` et `MAILPIT_SMTP_PORT` permettent de les changer localement avant `docker compose up -d` ; ne les exposez jamais publiquement. Copier `apps/api/.env.example` vers `apps/api/.env`, puis exécuter `node ace generate:key` depuis `apps/api` afin de renseigner localement `APP_KEY` sans commiter cette valeur. Enfin exécuter `npm ci`, `npm run migration:run --workspace=api`, `npm run dev --workspace=api` et `npm run dev --workspace=web` dans deux terminaux.

En développement, les messages de vérification et de récupération sont livrés à Mailpit. L'interface de l'application n'affirme jamais leur livraison effective à une boîte distante. Pour tester un parcours, créer un compte ou demander une récupération, ouvrir Mailpit, puis suivre le lien du message reçu. Mailpit ne sert ni la production ni la CI : la production utilise Resend et les tests API capturent les messages en mémoire.

`GET /health/live` vérifie uniquement le processus API. `GET /health/ready` vérifie PostgreSQL sans divulguer la configuration. `npm run test:integration` vise par défaut le PostgreSQL Compose local sur 5433 ; la CI fournit explicitement le port de son service éphémère (5432). Vérifier le socle avec `npm run build`, `npm test` et `npm run test:integration`.

`npm run audit` bloque les vulnérabilités high/critical. Les vulnérabilités low/moderate transitives éventuellement signalées restent à examiner dans la revue QA ; elles ne doivent pas être masquées ni faire baisser le seuil de la CI.
